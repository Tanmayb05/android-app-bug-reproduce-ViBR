## Top Recurring True Root Causes

1. **Scene detection granularity failures**: CLIP/SSIM either collapsed multiple real actions into one segment or over-segmented camera noise into many tiny segments. This is the most common primary failure.
2. **Replay environment/precondition mismatch**: dirty app state, missing data, unexpected modals, wrong folder contents, or non-reproducing target builds made correct replay impossible.
3. **Camera-captured input mismatch**: many source videos are phone-of-phone recordings, not screen recordings. Glare, blur, perspective, hands, cables, desks, walls, and notches become false UI evidence.
4. **GroundingDINO region detection failure**: small icons, text buttons, drawer controls, deck rows, and modal buttons were missed or merged into generic boxes.
5. **LLM ROI/action/recovery policy failure**: the model often chose adjacent plausible targets, wrong action types, or kept moving forward after the state checker already knew the device was off-path.

## Strong Evidence For A Research Contribution

The strongest research case is not "ViBR has bugs"; it is: **ViBR assumes clean screen recordings, but real bug reports may be camera-captured videos, and that input distribution breaks segmentation, detection, and state comparison.**

Strongest runs for that claim: 01C, 14A, 15C, 17C, 19A, 19C, 21A, 21B, 22A, 22B, 22C. These directly involve handheld/camera artifacts causing segmentation and detector failures. Additional detector-specific research evidence: 04C, 05B, 14C, 17A, and 22B, where GroundingDINO misses or merges mobile UI controls even when the target is visually central to the task.

## Engineering Cleanup

These are mostly fixable without a new research claim: 01B, 02A, 04A, 04B, 05A, 06A, 06C, 07B, 07C, 08A, 08B, 08C, 09A, 09B, 09C, 10A, 10C, 11A, 11B, 11C, 12B, 13A, 13B, 15A, 15B, 18A, 18B, 18C, 20B, 20C.

Main fixes:

- Make segmentation action-aware rather than one-action-per-segment.
- Add robust support for `type_text`, long-press, submit/search, backtracking, and incremental scroll.
- Re-run detection on the current live screenshot during recovery.
- Abort or re-anchor when state consistency repeatedly says the device is on a different path.
- Log full recovery candidate lists, match scores, and selected coordinates.

## Exclude From Research Claims

These runs should not be used as evidence that ViBR's method failed, except as benchmark-quality caveats: 03A, 03B, 03C, 05C, 06B, 10B, 12A, 12C, 14B, 16A, 16B, 16C, 17B, 20A, 21C.

Reasons: stale device state, wrong app state, video/ground-truth mismatch, missing app data, premium feature mismatch, non-reproducing bug environment, or provider quota exhaustion.

## Final Thesis

**ViBR fails mainly because** the segment stream often does not represent a clean sequence of executable user actions, and when the device drifts, the recovery loop continues making plausible local moves instead of re-anchoring or aborting.

**The strongest research gap is** robust reproduction from camera-captured bug videos. The original ViBR-style pipeline is built around screen-recording assumptions; camera videos add occlusion, glare, blur, perspective distortion, physical backgrounds, and capture flicker that break both segmentation and region detection.

**The engineering fixes are** cleaner environment reset, stricter benchmark validation, better action vocabulary, action-aware segmentation, live-frame re-detection during recovery, bounded scroll/gesture execution, and explicit abort/re-anchor logic after repeated state mismatches.
